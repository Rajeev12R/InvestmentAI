# PHASE 40 — VERSIONED INSTITUTIONAL REPORT TEMPLATES

## 1. Template Design Philosophy

Institutional reports require deterministic layout, strict section contracts, and backwards compatibility.

### Governing Rules
1. **Templates Are Immutable**: Once a template version (e.g. `TMPL-PORTFOLIO-OVERVIEW-V1` v1.0.0) is used by an approved report, it is permanently frozen. Subsequent improvements are released under a new version (v1.1.0 or v2.0.0).
2. **Deterministic Section Contracts**: Each template defines `requiredSections`. If any required section cannot be assembled from authoritative upstream data, generation fails with an explicit validation error.
3. **No Hallucinated Sections**: If data is missing or unavailable, sections are marked `available: false` with an explicit disclosure rather than generating fabricated placeholders.

## 3. Backwards Compatibility & Version Isolation

When an older report is verified or re-rendered:
* The system retrieves the exact `templateId` and `templateVersion` associated with that report.
* Future template releases do not retroactively alter the layout, styling, or section structure of previously finalized deliverables.
